# 02 设计哲学

## 五条设计信条

### 第一信条：可读即可协作

程序首先是写给人与智能体共同阅读的文本。

- **前导类型范式**：类型在前、名称在后——函数签名即文档，局部上下文即可推断行为
- **单一惯用法**：每种意图只有一种推荐表达，消除歧义与随机选择
- **声明式查询**：以 Query 语法表达数据变换，而非命令式循环堆砌
- **确定性格式**：源码存在唯一的规范形式，人类与智能体输出一致

### 第二信条：安全在编译期完成

运行时崩溃是设计的失败，不是程序的常态。

- **资源所有权**：`struct` 栈上分配按值移动；`class` 堆上分配、由引用计数（ARC）共享所有权；编译器在借用检查阶段追踪生命周期
- **借用约束**：可变与不可变访问互斥，拒绝数据竞争
- **穷尽匹配**：分支必须覆盖所有可能，拒绝静默遗漏
- **显式错误链**：可失败操作在类型中标记，`?` 传播错误，失败不可被忽略

### 第三信条：行为在编译期确定

可预测性是系统软件的底线。

- **纯 AOT 编译**：源码直接变为原生机器码，无解释、无即时编译
- **无停顿式回收**：拒绝全局垃圾回收，资源释放时机可预测
- **零成本抽象**：泛型单态化，迭代器与 Enumerable 路径栈分配，抽象不引入隐式堆开销
- **确定性输出**：相同源码、相同工具链、相同目标平台，产生相同二进制

### 第四信条：代码即数据

程序的结构本身应成为可分析、可变换、可传递的数据。

- **表达式树（`Expression<T>`）**：Lambda 可被提升为编译期常量数据结构，写入只读段
- **Provider 模式**：查询引擎、验证器、规划器直接遍历静态树，无需运行时解释；SQL 等具体翻译由标准库 Provider 实现，非编译器内置
- **双路径查询**：Enumerable 路径零成本迭代；Queryable 路径编译期树化

### 第五信条：为人机共写而生

Arc 从设计原点出发，将智能体视为一等协作伙伴。

- **结构化诊断**：编译器输出机器可读的精确错误，附带修复建议
- **局部推理**：函数签名与邻近上下文即可理解行为，无需全项目图谱
- **能力显式**：外部效应（I/O、网络、系统调用）在类型签名中标记，沙箱可审计
- **契约可声明**：前置条件与后置条件作为类型系统的一部分

## 语法传承与 AI 优先裁决

Arc 不追求语法的全面创新，而是取市面上语言语法最优雅的一面；创新集中于面向 AI 时代的语义结构（`.arcgr`、`.ani`、表达式树、能力显式），而非表面语法符号。

**一句话原则：语法取最优雅，语义取最严谨。**

| 借鉴来源 | Arc 中的体现 |
|---------|------------|
| **C#** | 语法基底、`namespace`、属性、LINQ、委托、`async`/`await` |
| **Rust** | 零成本抽象、单态化泛型、所有权思维（ARC 替代 GC） |
| **Swift** | 协议导向（`IEnumerable<T>`）、值/引用类型区分 |
| **Zig** | 无隐藏控制流、显式错误（取代 `unsafe`/`extern "C"`） |
| **Go** | 无中央包注册表（git + semver） |

### AI 优先裁决

当人类语法优雅与 AI 语义清晰冲突时，Arc **倾向于 AI 清晰**。人机共写并非对称关系：人类可适应略繁的语法，而智能体在隐式语义下采样方差显著放大。牺牲少量人类便利换取 AI 可靠性是净收益。三条子规则：

| 子规则 | 含义 |
|-------|------|
| **显式 > 隐式** | 契约、类型、效应在源码表面可见 |
| **单一 > 多元** | 同一意图只有一种推荐形式 |
| **报错 > 静默推断** | 不支持的写法应显式错误，而非猜出一种行为 |

### 应用裁决的触发条件

当设计出现以下任一情形时，必须援引本节裁决：

1. 新特性引入语法选择——优先继承成熟形态，不发明
2. 新特性出现人机冲突——倾向 AI 清晰
3. 新特性涉及显式/隐式取舍——默认显式
4. 新特性涉及多写法并存——默认拒绝并存
