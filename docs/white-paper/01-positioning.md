# 01 语言定位

## Arc 为何存在

智能正在重塑软件的编写方式。当代码的主要生产者从单一的人类扩展到人类与智能体的协作体时，编程语言必须重新回答三个问题：

- **谁能读懂它？**
- **谁能安全地修改它？**
- **谁能预测它的行为？**

Arc 是为回答这些问题而生的系统级语言。它以编译期验证保证安全与确定性，以 C# 惯用的表面语法保证可读性，以面向智能体的语义结构保证可协作性。

Arc 是**纯 AOT 编译型**系统级语言：强类型、C# 惯用表面语法，核心抽象（类型、LINQ、`Expression<T>`、编译期元编程）在**编译期与链接期**完成，而非运行时解释。运行时仅执行已物化的机器码与静态数据。

## 命名

**Arc** 取「弧」——连接意图与执行的桥梁，连接人类思维与机器行为的纽带。在智能时代，编程语言不仅是人与计算机的接口，更是人与智能体协作的公共协议。

源码扩展名为 **`.as`**，编译器命令为 **`arc`**。

## 四元设计方程

```
Arc = 可读性 × 编译期安全 × AOT 确定性 × 人机协作性
```

四个因子**相乘**而非相加——任何一项为零，语言价值归零。

## 边界

### Arc 追求

- 人类读得自然，智能体写得准确，编译器验得严格，机器跑得快
- 成为智能时代系统编程的公共协议

### Arc 拒绝

- 隐式魔法与不可预测的运行时行为
- 以运行时反射替代编译期验证
- 多种等价写法并存的语法冗余
- 将智能体适配视为事后补丁而非设计原点

## 与既有生态的关系

Arc 是独立语言，非 Rust DSL，也非 C# 的运行时移植。它借鉴 C# 的表面语法、Rust 的零成本抽象与所有权思维、Swift 的协议导向、Zig 的显式错误、Go 的声明式包管理——但每一项借鉴都经过编译期验证与 AOT 确定性筛网过滤，剔除与四元方程冲突的部分。
