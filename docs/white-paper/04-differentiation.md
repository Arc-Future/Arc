# 04 差异化价值

Arc 面向智能时代，将人类开发者与智能体视为对等的协作伙伴。其差异化集中在**面向 AI 时代的语义结构**，而非表面语法符号的发明。

## 面向智能体的结构化创新

| 创新点 | 面向 AI 的价值 |
|-------|--------------|
| `.arcgr` 语义索引 | AI 工具链原生消费结构化语义，无需正则扒源码 |
| `.ani` 验证式 FFI 契约 | AI 生成 FFI 调用时可在编译期验证符号可靠性 |
| `arc-server` LSP 复用编译器 IR | AI 工具链与人类工具链共享同一份语义源 |
| 表达式树作为编译期常量 | AI 生成的查询可静态分析，而非运行时试错 |
| 结构化诊断 | AI 可精确消费错误位置与修复建议 |

## 结构化诊断

编译器通过 `codespan-reporting` 输出带源位置的结构化诊断，供人类阅读与工具机器解析。每条诊断包含级别、消息、标签（文件/span/文本）与相关说明。

错误类型在各编译阶段以枚举定义，CLI 层映射为 `Diagnostic`。规划中的 `--message-format json` 将输出机器可读的错误码、消息与 span，智能体优先解析 JSON 通道。诊断消息应包含**可操作建议**，而非仅陈述失败。

## 代码即数据

程序的结构是可分析、可变换、可传递的数据：

- **表达式树（`Expression<T>`）**：Lambda 提升为编译期常量数据结构，写入只读段
- **Provider 模式**：查询引擎、验证器、规划器直接遍历静态树，无需运行时解释
- **双路径查询**：Enumerable 路径零成本迭代；Queryable 路径编译期树化

## 能力显式

Arc 将外部效应（I/O、网络、窗口、文件系统）设计为可审计的显式能力。智能体与人类读者均可从 API 表面判断程序可能触达的边界，无需全项目数据流分析。

- **namespace 级能力声明**：`namespace X capability io, db { ... }`，沿父链继承取并集
- **`.ani` 契约强制**：调用方所在 namespace 必须声明包含调用目标能力，否则 typeck 拒绝
- **沙箱/Agent（规划）**：默认拒绝未声明能力，opt-in 白名单

## 对开发者的价值

- **可读**：C# 惯用表面语法，前导类型范式，函数签名即文档
- **安全**：所有权、借用约束、穷尽匹配、显式错误链，全部在编译期完成
- **确定**：纯 AOT、无停顿式回收、零成本抽象、确定性输出
- **可审计**：能力显式，智能体行为可沙箱

## 对智能体的价值

- **可预测**：显式 > 隐式，单一 > 多元，报错 > 静默推断
- **可分析**：`.arcgr` 语义索引、结构化诊断、表达式树静态遍历
- **可验证**：验证式 FFI 契约、编译期能力检查
- **可协作**：与人类共享同一编译器 IR 与语义源
