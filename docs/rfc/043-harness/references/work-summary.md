# 回合小结与偏差判定

> 关联 [043(../../043-harness.md) §6 · §8。本子项定义每工作单元的**小结格式**（领导偏差判定的主表面）。偏差触发见 [纠偏协议](anchor-correction-protocol.md)；事实源为当前 [AIRfc](airfc.md) Revision。宣称门闩见 [llm-gates](llm-gates.md)。

## §0 宣称门闩

| # | 门闩 |
|---|------|
| 1 | 一工作单元结束必须产出小结；无小结 → 禁止宣称该单元完成 |
| 2 | 「对齐」对照当前 **AIRfc Spec**（Intention / Design / Acceptance），不用散落对话当事实源 |
| 3 | 有绕过 / 发现偏差未上报 → 禁止合入宣称（见 llm-gates G-M6） |

## 目的

复刻真实研发团队的跟进逻辑：**领导不重读代码，看"结构一致性 + 行为对照需求 + 员工的总结反馈"**。每完成一个工作单元（一步 / 一工具批 / 一回合），Agent 产出结构化小结，人/监控层**从小结判定偏差**，而非重读 diff。

## 小结格式（精炼模板）

每字段 ≤1 行，领导 30 秒读完并给出判定。小结是**决策面**，不是聊天记录。

```text
■ 小结 <单元 id>
  做了什么  <改动摘要，≤2 行>
  对齐      <设计 ✓/偏差点 · 需求 ✓/偏差点>
  验证      <命令> <绿/红> · 新增用例 N · 覆盖对照需求
  困难/绕过 <无> | <困难+解决> · 原则 ✓/✗ · 绕过 有/无（有必上报）
  发现      <无> | <架构/需求/边界问题>（有 → 触发评审）
```

## 字段语义

| 字段 | 内容 | 判定用途 |
|------|------|----------|
| 做了什么 | 本单元改动摘要（≤2 行） | 领导看改动范围 |
| 对齐 | 设计/需求逐条对照：✓ 或单列偏差点 | 触发纠偏（架构/需求偏差） |
| 验证 | 验证命令 + 结果（绿/红）；新增用例数；覆盖是否对照需求逐条 | 防降级/回归判定 |
| 困难/绕过 | 遇到的困难 + 解决方式；是否违反原则、有无绕过（**必答**，有绕过必须上报） | 暴露原则违背/绕过行为——最危险的偏差 |
| 发现 | 架构设计不足、需求分析不到位、边界场景不足等（无 / 有 → 触发评审） | 设计健康检查 / 需求补强 |

## 精炼原则

| 原则 | 契约 |
|------|------|
| 暴露不确定性 | 小结必须显式写出"假设"与"未决"；不是罗列成果，是透明化决策 |
| 必答字段 | 困难/绕过、发现 为**必答**（无 → 写"无"），禁止省略 |
| 一单元一小结 | 每完成一个工作单元即产出；不攒批、不事后补 |
| 偏差判定 | 人/监控层从小结判定：偏离 → 纠偏；合规 → 放行 |
| 问询衔接 | 小结里未解决的不确定性 = 下一个**主动询问**的起点（见偏差检测机制） |

## 判定路径

D7 人验收门从"最终验收"扩展为"**每单元小结 → 偏差判定 → 纠偏或放行**"的连续手递手：

```text
单元完成 → 小结生成（5 字段） → 偏差判定
   ├─ 合规 → 放行进入下一单元
   ├─ 可自动修复 → 修复（≤3 轮）
   └─ 偏离/升级 → 纠偏（AIRfc 升版）或人确认（协作确认点）
```

与 D5 自审的关系：D5 是**终局自审**（对照 AIRfc 验收面附可执行证明）；小结是**每单元自审**（对照当前 AIRfc 暴露偏差）。两者互补，不重复。

## 示例

```text
■ 小结 step-2
  做了什么  新增 AgentHost.BuildOptionsAsync 的计划门闩装配
  对齐      设计 ✓（按 §10 落地归属）· 需求 ✓（PlanGatedCapabilities 生效）
  验证      arc build examples/ArcAgent 绿 · 新增用例 2 · 覆盖对照需求逐条 ✓
  困难/绕过 无
  发现      无
```
