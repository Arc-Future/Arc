# 纠偏协议（AIRfc）

> 关联 [043(../../043-harness.md) §2 · §4 · [AIRfc 体系](airfc.md)。本子项定义**修复 / 纠偏分流**、偏差检测与决策轨迹语义。AIRfc 聚合根与 Spec 面见 airfc；本篇不重复「四散字段」表述。

## 唯一事实源

执行环对照的唯一事实源是当前 **AIRfc Revision**（含 Intention / Design / Acceptance Spec 面，以及引用的 `AIPlan`）。任何方向变更只升版 AIRfc，不散落于对话。

## 版本化协议

| 面 | 契约 |
|----|------|
| 版本号 | AIRfc 统一步进（Revision+1）；Plan 面变更走 `AIPlan` 修订协议并反映到同一 Revision 轨迹 |
| 版本记录 | 写入 Agent 会话事件日志（决策轨迹）：旧方向 → 新方向 → 原因 |
| 时效 | 执行环始终以**最新 Revision** 为基准；旧版只读审计 |

## 修复 / 纠偏分流

```text
                  ┌────────── 方向环（人的主场）──────────┐
  用户补充方向 ──→ │ AIRfc Spec 升版（+ AIPlan 复用）     │ ── 纠偏：升版，非推翻
                  └──────────────┬───────────────────────┘
                                 │ AIRfc（唯一事实源）
                                 ▼
                  ┌────────── 执行环（机器的主场）──────────┐
  实现改动 ──────→ │ DoD 门（Coding：D0–D7）               │ ── 修复：迭代 ≤3 轮
  验证失败          │ 绿点快照 · 决策轨迹                     │     超限回滚绿点
                  └──────────────┬───────────────────────┘
                                 ▼
                    AIRfc 内部矛盾 → 升级人纠偏
```

| 信号 | 事实 | 分流 |
|------|------|------|
| 验证失败（D0–D3 不绿） | 实现偏离当前 AIRfc | **修复**：结构化反馈喂回（≤3 轮）；超限回滚绿点 + 升级人 |
| 需求/意图变化 | 用户补充方向 | **纠偏**：AIRfc Revision+1 → 执行环重对齐 |
| Spec 内部矛盾 | 测试互斥 / 设计盖不住新方向 / AIPlan 够不到验收 | 升级人纠偏（机器发现矛盾，不擅自改意图） |

## 偏差检测机制（触发信号）

| 触发源 | 可执行信号 | 判定 | 分流 |
|--------|-----------|------|------|
| 破坏架构 | diff 违反 Design 面声明的架构约束 | 代码图机械校验 | 可恢复→修复；设计要改→升版评审 |
| 设计不足 | 执行暴露设计假设不成立 | 对照 Design「为什么」 | 设计调整须评审，不得静默改 |
| 与需求不符 | 行为对照 Acceptance 失败 | D5 自审 | 测试绿但行为不符→升版或人确认 |
| 测试降级 | 改弱/删测/特判过关 | 验收面属 AIRfc + 防降级门 | 拦截升级；改测=纠偏 |
| 主动询问 | 需求二义 / 无法推导 | HITL ProvideInput | 询问是一等动作 |
| 回合总结 | 小结暴露偏差 | 领导从小结判定 | 偏离→纠偏；合规→放行 |

### 测试属于 AIRfc 验收面

- 测试先行锁定（见 [testing-first](testing-first.md)）；实现阶段不可擅自改已批准测试；  
- 改/删/削测试 = **AIRfc 纠偏**，须评审；  
- 反降级规则见 [definition-of-done](definition-of-done.md)。

## 决策轨迹（事件语义）

| 事件 | 承载 |
|------|------|
| `airfc:created` | AIRfc 初始 Revision |
| `airfc:revised` | 旧 → 新 → 原因 → 增量说明 |
| `airfc:rejected` | 用户拒绝计划/设计/验收 |
| `checkpoint:green` | 绿点 |
| `checkpoint:rollback` | 回滚目标 + 原因 |

与 038 `approval` 事件并列构成完整决策轨迹。历史别名 `anchor:*` 视为 `airfc:*` 的过渡名。

## 挂账追踪闭环（三态）

> 来源：[harness-llm-lessons](harness-llm-lessons.md)（B7 机制 · P0-3）。挂账项 = 纠偏 / 修复 / 排期过程中登记但未当次闭环的遗留项（如 plan.md「挂账」、references「待排期」、CD 表「未修」等）。**禁止登记即忘**。

### 三态

| 态 | 定义 | 约束 |
|----|------|------|
| 已修 | 对应缺陷 / 遗留已消除并经复验 | **必须带可复验证据**（e2e 名 / `文件:行` / 探针）；禁空口「已修」 |
| 仍挂 | 仍未闭环，登记为待排期 | **必须带下次核实点**（下次排期 / 复查时机 / 阻塞前置） |
| 已过时 | 因方向变更 / 收敛 / 替代方案而不再成立 | **必须带过时原因**（被什么替代 / 为何不再需要），防「改口成已过时」掩盖烂尾 |

### 闭环流程

```text
登记（挂账项 + 证据 + 下次核实点）
   → 核实（对照证据链：e2e / 文件:行 / 探针 / 命令 trace）
   → 更新（三态取一：已修（带证据）/ 仍挂（带核实点）/ 已过时（带原因））
```

- 「已修」不得只写结论：须给出**可复验证据**（`arc_ai_*_e2e` 用例名 / `文件:行` / 探针路径），无证据视为「仍挂」。
- 每次触及挂账项所在文档 / 代码，须顺带更新其状态（已修 / 仍挂 / 已过时），禁止积累过期登记。
- 挂账追踪与 [回合小结](work-summary.md) 偏差判定并列：小结暴露偏差 → 纠偏 / 挂账 → 本闭环三态追踪。
