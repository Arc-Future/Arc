# RFC 033 LSP 服务化

## 背景

Arc 原生 LSP 实现由 `arc-server` 长驻进程提供，经 JSON-RPC over stdio 遵守 LSP 3.17 与编辑器通信。根本设计原则：**复用编译器 crates**（parse / hir / typeck / borrowck / arcgr），不重写语义——这是与 rust-analyzer 等「自建语义」的根本区别。编译器是唯一语义源，LSP 仅是语义的面向前端（信条「为人机共写而生」）。

`.arcgr` 语义索引（见 [034](034-ai-toolchain-arcgr.md)）是 LSP 的共享数据底座：语义 provider 消费 `.arcgr` 的 SymbolTable / ReferenceTable 提供跨文件、跨包查询。

## 设计决策

### 1. 架构

```
                    ┌─────────────────────────────┐
  编辑器 (LSP 3.17) │        arc-server            │
   JSON-RPC/stdio   │  ┌───────────────────────┐  │
 ──────────────────▶│  │ 编译器 crates 复用      │  │
   didOpen/query ──▶│  │ parse→hir→typeck→arcgr │  │
   ◀── response ◀───│  │ (单一语义源)            │  │
                    │  └───────────────────────┘  │
                    └─────────────────────────────┘
```

- 语言无关的协议层与编译器语义解耦；语义能力全部委托编译器 crates。
- DAP 调试能力（见 [035](035-debugger.md)）与 LSP 分离，由独立服务承载。

### 2. 能力矩阵

| 能力 | 机制 | 说明 |
|------|------|------|
| `initialize` / `initialized` | 协议握手 | 建立会话，声明能力 |
| `textDocument/didOpen` `didChange` `didClose` | 文本同步 | 增量维护开放文档状态 |
| `textDocument/definition` | 语义 provider | 基于 `.arcgr` 符号表定位声明 |
| `textDocument/references` | 语义 provider | 基于引用表聚合全部引用 |
| `textDocument/hover` | 语义 provider | 类型/签名/文档注释 |
| `textDocument/documentSymbol` | 语义 provider | 文档级符号大纲 |
| `textDocument/completion` | 语义 provider | 补全候选 |
| `workspace/symbol` | 跨包聚合 | 跨主包与依赖包聚合符号（见 §4） |
| `textDocument/publishDiagnostics` | 诊断推送 | 结构化诊断（见 §5） |

### 3. 增量与多文件

开放文档为**真源**（source of truth）：编辑器打开中的文档内容覆盖语义索引中的源码版本，保证查询反映当前编辑态。

| 机制 | 内容 |
|------|------|
| 文本同步 | `didOpen` / `didChange` / `didClose` 维护文档缓冲 |
| 惰性重解析 | 变更触发惰性 SyntaxTree 重解析，避免全量重建 |
| 语法 provider | 语法级能力（completion 骨架、语法高亮辅助）即时响应 |
| 语义 provider | 语义级能力经 typeck 刷新，依赖 `.arcgr` 增量更新 |

### 4. 跨包查询与 Project 体系

**Project 体系**统一主包与依赖包：`arc.toml` 驱动主包及依赖包自动加载，`ContextManifest` 的 L0 上下文并入 Project 统一管理。

| 能力 | 机制 |
|------|------|
| 主包加载 | 由 `arc.toml`（manifest）定位项目根与入口 |
| 依赖包加载 | 由 `arc.toml` `[dependencies]` `path` 声明定位依赖项目源码 |
| 跨包 Goto Definition | 主包符号可定位到依赖包声明 |
| `workspace/symbol` | 跨主包 + 依赖包聚合符号，统一查询 |

### 5. 诊断

LSP 复用编译器结构化诊断通道（与 `--message-format json` 同源），将 parse / typeck / borrowck 诊断推送为 `publishDiagnostics`。诊断信息与 CLI 输出一致，保证编辑器与命令行行为对齐。

### 6. 拒绝项

| 项 | 裁决 |
|----|------|
| 自建语义分析 | 拒绝——必须复用编译器 crates，LSP 不重写语义 |
| 语义与 CLI 分叉 | 拒绝——诊断与定义均以编译器单一语义源为准 |
| workspace 多进程管理 | 不在本设计面内——单进程服务承载能力集 |

## 边界

- **`.arcgr` 语义产物格式**与 AI 工具链消费见 [034](034-ai-toolchain-arcgr.md)；本 RFC 只讲 LSP 服务。
- **调试器与 DAP**见 [035](035-debugger.md)。
- **编译器管线**见 [013](013-compiler-pipeline.md)。
- **`arc-server` 服务期产物**（`.arcgr`、`.xml`）从源码直接生成（`arc inspect`），见 [031](031-compiler-cli.md) 与 [017](017-build-artifacts-packages.md)。
