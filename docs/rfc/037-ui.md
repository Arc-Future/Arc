# RFC 037 UI 声明式框架

## 背景

Arc.UI 是 Arc 的声明式界面框架：以 **ARML** 标记语言描述界面、以 **WPF 对齐**的样式与数据绑定驱动更新、以 **wgpu** 为 GPU 渲染后端、以**虚拟化**承载大数据量列表、以**自适应布局**覆盖多平台多分辨率、以**显式装配**（源码打包合并单一编译单元）完成装配。它面向桌面 AOT 优先，走**单一惯用法**——同一意图一条正道，拒绝多轨（命令式/声明式双轨、渲染后端多轨、绑定语法双轨）。

Arc.UI 是纯标准库领域层：语言级泛型、表达式树、可空与绑定机制见对应语言 RFC；GPU 渲染属本框架内部实现。它不依赖编译器核心提供领域逻辑，仅消费既有语言能力（源码打包合并单一编译单元后符号全局可见）。

## 设计决策

### 1. 定位与单一惯用法

| 面 | 正道 | 拒绝 |
|----|------|------|
| 界面描述 | 声明式 ARML 标记 | 纯命令式构建器作为主路径（元素密集难写、diff 噪声大） |
| 渲染后端 | 单一 wgpu 后端（WgpuRender） | 多后端双轨；手写软件渲染主路径 |
| 绑定语法 | 数据绑定 + 编译期校验 | 多套绑定 DSL 并存 |
| 装配 | 编译期显式注册（源码合并单一编译单元） | 运行时反射扫描 |

ArcUI 标准库代码须严谨实现、作典范级水平；禁止半成品与降级实施。

### 2. 命名空间分层

| 命名空间 | 内容 | 归属 |
|----------|------|------|
| `Arc.UI` | 基类根命名空间（`Element`、`Application`、`ResourceDictionary`、绑定/通知原语） | 根 |
| `Arc.UI.Components` | 派生组件（`Window`、控件） | 子 |
| `Arc.UI.Components.Layout` | 布局组件 | 子 |
| `Arc.UI.Rendering` | `IRender`（基类） | 子 |
| `Arc.UI.Rendering.Wgpu` | `WgpuRender`（派生） | 子 |

**层级原则**：基类放根命名空间 `Arc.UI`，派生实现在子命名空间 `Arc.UI.XXX`。子命名空间天然引用穿透父命名空间类型（合理方向）；反方向（基类在子、派生在另一子）为反模式。目录可解耦于命名空间（如 `std/UI/Core/Data/Signal.as` 可归 `Arc.UI`），但命名空间必须遵守基类在上、派生在下。

### 3. ARML 标记与数据绑定

ARML 是声明式标记语言，采用 **WPF xaml 心智模型**：标记 + code-behind + 强类型 DataContext，绑定路径在**编译期对照模型类型解析**（绑错属性名/类型不匹配即编译期报错）。

| 机制 | 形态 | 语义 |
|------|------|------|
| 标记 | `*.arml` 文件 | 声明式界面树 |
| code-behind | 配套 `*.as` | 生命周期与逻辑 |
| 数据绑定 | `{Binding Path}` / `{}` 标记 | 属性路径投影，复杂逻辑在模型预计算 |
| 通知 | `[Observable]` 特性 | 属性变更通知，触发绑定刷新 |
| 集合 | `ObservableCollection<T>` | 集合变更通知 |

```arml
<Window x:Class="Demo.MainWindow" Title="{Binding Title}">
    <StackPanel vertical="true" Padding="16">
        <TextBlock Text="{Binding Greeting}" />
        <Button Content="点击" Command="{Binding Click}" />
    </StackPanel>
</Window>
```

`[Observable]` 与 `ObservableCollection<T>` 均带生命周期管理：弱引用避免长生命周期宿主泄漏，确定性退订（`Unsubscribe(token)`）保证不悬挂。

**列表数据面（强类型）**：集合类控件（ItemsControl 派生系）的数据源唯一入口 `ItemsSource` 经 `ItemSourceView` 数据源视图物化——**object 数据本体管道**（`ItemAt` 返数据本体 / `DisplayAt` 返显示投影），对标 WPF「ItemsSource 承载任意 CLR 对象」。显示投影在视图构造期以 `Func<T,string>` / `EnumOptions<T>` 烘焙（编译期类型检查，非运行期字符串反射路径——`DisplayMemberPath` 类运行期字符串投影不设）；选中态（`SelectedItem`）与多选态（`SelectedItems`）承载**数据本体**而非显示字符串。

**样式系统（x:Key 统一资源键）**：`<Style x:Key TargetType BasedOn>` + Setter/Trigger 定义于资源容器（`<Window.Resources>` / `<Grid.Styles>` 嵌套容器上浮注册进窗口级字典）。元素端**多资源绑定**唯一写法 `Style="{StaticResource K1, K2}"`——多键依次应用、优先级递增（后应用者覆盖同名属性），叠加语义由多键承担；**不设样式类体系**（MAUI `StyleClass`/CSS 类的第二套字符串 tag 标识不引入——x:Key 已是唯一资源标识，双标识即双轨）。编译定型：键全部命中窗口字典 → codegen 直接引用注册的 Style 对象（单键直赋 / 多键定型对象列表，运行时零字符串查找）；任一键不可解析（App 全局/主题域）→ 逗号分隔请求键字符串，应用期经解析链逐键解析。隐式样式（无 `x:Key`）按 `TargetType` 自动应用；`BasedOn` 继承链先父后子（编译期 verify 检环 + 运行时 visited 兜底）。应用趟序：隐式（TargetType 命中）→ 显式（绑定产物，显式意图优先级最高）。

### 4. 渲染与虚拟化

| 面 | 决策 |
|----|------|
| 渲染后端 | wgpu（`Arc.UI.Rendering.Wgpu.WgpuRender` 实现 `IRender`） |
| 渲染循环 | 数据驱动 + 脏区局部更新，避免全树重绘 |
| 虚拟化 | 大数据量列表只物化视口内条目，滚动按需回收/创建 |
| 主题 | 内置主题经 arml 定义（Light/Dark），`Application` 为唯一解析根，编译期扁平化聚合 |
| 画质路线 | 渲染/字体画质提升路线图见 [rendering-quality-path](037-ui/references/rendering-quality-path.md) |

主题资源分层：色值经 `std/UI/Core/Themes/*.arml` 定义（权威与生成链见 [builtin-theme-resources](037-ui/references/builtin-theme-resources.md)；运行时由 `BuiltInTheme.Colors.g.as` 填入字典），几何/深度/时长经代码（`BuiltInTheme` 的 `CornerRadius`/`Elevation`/`motion`）定义。`SwitchTheme("Light"/"Dark")` 一条调用全链生效。色值 ARML 为单一源；控件隐式 Style 单一落点 `Controls.arml`（仅 chrome，字体禁入见 §4）。Style Setter 引用主题色唯一写法 `{StaticResource Color.*}`——Theme 本身即资源（活动主题经 `MergedDictionaries` 并入 `Application.Resources` 解析链，本地条目优先），键编译期确定、值应用期按当前活动主题解析落值；`SwitchTheme` 换活动字典后**重新应用隐式样式**刷新 Setter 落值（`SetStyleValue` 样式通道本地值优先，不冲用户程序化覆盖），无独立主题资源引用词法（不设 `{ThemeResource}`/`{DynamicResource}`）。

**全局样式与属性值继承**：环境属性能力由**注册期元数据**声明——DP 经 `RegisterInheritedProperty` 工厂注册（内部以 `FrameworkPropertyMetadata(Inherits)` 元数据声明，对标 WPF `FrameworkPropertyMetadataOptions.Inherits`；选项位掩码沿用 `AttributeTargets` 的 class + const int 先例），继承属性集登记于 `DependencyPropertyRegistry`（注册驱动，**零硬编码**，任何 DP 经此工厂注册即入体系）。`FontFamily`/`FontSize`/`FontWeight`/`Foreground` 以此注册——Window/根容器设置一次全树生效，子控件零重复书写；值优先级 **本地值 > 样式 Setter > 最近祖先有效值 > DP 默认值**（祖先的样式值亦为有效值）。

**推送式继承（功能与性能双收）**：继承采用**写时向下传播**（WPF 同构）而非读时遍历——`SetValue`/`SetStyleValue` 沿子树传播 **Signal 引用**（子孙有本地/样式值则屏蔽，并以该值为子树新源续传，最近祖先语义）；`AddChild` 挂接时自祖先链一次性重算继承槽。性能契约：**读 O(1)**（本地/样式槽 → 继承槽 → 默认值，三次字典探测内）；静态 ARML 树在**构建期一次固化**（Arc 编译期确定哲学——构建后值即固效，运行期零遍历）；动态祖先改值只付受影响子树成本，且因传播的是 Signal 引用，祖先后续改写全子树读值即时一致。资源隔离边界（`VisualHost`）截断资源解析，**不截断环境属性继承**（WPF 同构：环境值流动 ≠ 资源查找）。全局字体默认**单一源** = `Control` DP 默认值；控件隐式 Style（`Themes/Controls.arml`）**禁承载字体 Setter**，只承载 chrome（内边距等）且不烘焙静态色。诚实边界：动态拆离（Detach API 未提供）与「绑定观察继承值变更通知」为后续项；DataContext 继承独立机制（边界语义），后续随边界选项收敛入本体系。

```arml
<Window FontFamily="Microsoft YaHei" FontSize="14">
    <StackPanel>
        <TextBlock Text="{Binding Greeting}" />   <!-- 继承 Window 字体，零重复 -->
        <TextBlock Text="小字" FontSize="12" />    <!-- 本地值覆盖继承值 -->
    </StackPanel>
</Window>
```

### 5. 自适应布局

自适应以**类型安全值元素 + 结构化 `Match` 条件**承载：编译期枚举状态空间、运行期投影到目标平台/分辨率。

```arml
<Double x:Key="Spacing.Page">
    <Match Tier="sm" Value="8" />
    <Match Tier="md" Value="16" />
    <Match Tier="lg" Value="24" />
    <Match Value="16" />
</Double>
```

| 机制 | 决策 |
|------|------|
| 值元素 | 强类型（`Double`/`Thickness` 等），非裸字符串 |
| `Match` | 结构化条件投影，支持多维度（`Tier` 等） |
| 编译期 | 状态空间编译期枚举，杜绝拼写错误 |
| 运行期 | 按当前环境选择值 |

横向/纵向等常量作强类型枚举设计（对标 WPF），不用裸字符串。

### 6. 显式装配（源码打包）

源码打包下依赖源码合并进**单一编译单元**，全部符号编译期全局可见——装配即编译单元内的**显式静态注册**：宿主显式调用注册入口（或经静态构造器初始化），运行时零反射扫描。UI 侧贡献（菜单、状态栏、标签页）经同一显式注册面聚合到宿主。

| 面 | 决策 |
|----|------|
| 声明 | 显式注册调用 / 静态构造器（纯语言机制，无编译器特判） |
| 装配 | 宿主接收贡献直接绑定为 ViewModel，经数据绑定 + 槽位定制呈现 |
| 拒绝 | 运行时程序集扫描、运行时反射发现、编译器核心内置的声明式聚合特判 |

菜单/状态栏支持数据绑定 + 槽位/模板设计，实现完全 MVVM 数据驱动业务-UI 交互。标签页关闭按钮遵循 VSCode 风格（激活态常显、非激活态悬停显）。

### 7. UI 线程调度器（M-AS1）

UI 帧泵与调度器为**内部骨架（M-AS1）**，应用作者使用 `Application.RunAsync` 与 `await OpenPathAsync` 等正道入口，不直接操作调度器内部（对标 WPF 拒绝 `Dispatcher` 手工控制的反模式表）。

| 面 | 决策 |
|----|------|
| 工作队列 | `UiDispatcher.Post(UIPriority, Action)` 固定槽位队列（≤8 个挂起 Post），后台线程 → UI 线程的唯一窄通道 |
| 帧泵 | `FramePump.PumpOnce`：先 `DrainPostedWork` 排空调度队列，再 `EventPoll` 轮询原生事件；按需渲染（脏标记 + MotionEngine 插值帧） |
| 非阻塞正道 | `FramePump.RunAsync` 非阻塞骨架（`await Task.Delay(0)` 让出）；`RunUntilClose` 为阻塞演示兼容入口，**非终态** |
| 诚实边界 | M-AS1 仅固定槽位队列，尚无 EventLoop waker 合并；`InvokeAsync` 自非 UI 线程投递时不等待完成（留待 M-AS2） |
| 禁止 | `async void`；阻塞式 UI 线程调用；把 `UiDispatcher` 当用户级细粒度控制 API |

`UiDispatcher` 内部骨架：`CheckAccess` / `MarkUIThread` / `Post(UIPriority, Action)` / `InvokeAsync` / `DrainPostedWork`。UI 工作优先级取 M-AS1 子集（Idle/Loaded/Normal/Input/Render/Send），不做 WPF 十级 `DispatcherPriority` 克隆。长 I/O 与 CPU 路径必须经 `Post` 投递而非在 `EventPoll` 内阻塞。

### 8. 焦点、键盘与文本输入（M-focus2 · M-input · M-textbox）

输入栈以三条原则立契（对标 WPF 键盘焦点模型 / iced shell→widget 事件面；TextBox 文本内核契约与 TextBlock/TextBox 命名见 [text-editing](037-ui/references/text-editing.md)）：

**P1 单一焦点权威**：`FocusManager` 是键盘焦点唯一真相，注册表动态容量；`ImeBridge` 降级为跟随者（订阅焦点变化，TextBox → 关联 IME 上下文，非 TextBox → 解除），不再持有独立焦点决策面。平台层零焦点状态（`rt_ui_ime_set_focus` 仅服务 IME 组字目标路由，键盘事件不依赖它 gating）。

**P2 单一键盘通道**：平台层只做机械转换——`WM_KEYDOWN → rt_ui_dispatch_key(vk, mods)`、`WM_CHAR → rt_ui_dispatch_text(utf8)`（与 IME commit 同语义）；`WM_IME_*` 组字是唯一必须留在平台层的逻辑。编辑语义（Shift 扩选、Ctrl+A、Home/End、Delete 方向）**全部**在 `TextBoxModel` 内核（`TextBoxController` 做键命令→内核操作映射），平台层禁做修饰键分支。`KeyboardRouter` 按焦点类型分发：焦点在 TextBox → 编辑命令；否则 → Tab/方向导航。

**P3 无静默丢弃**：注册表满 / 路由未命中 / 状态失配必须有显式告警出口（`Console.WriteLine`），禁止静默 return。窗口失焦（WM_KILLFOCUS）由平台层清 IME 关联并通知，Arc 侧禁止单边清理（焦点写入单一方向：FocusManager → ImeBridge → 平台）。

| 面 | 决策 |
|----|------|
| 焦点注册 | `FocusManager.RegisterTabStop` 动态容量注册表（List 单态化就绪前 ≥64 槽 + 溢出告警）；过滤不可聚焦/非 TabStop/禁用控件 |
| 焦点出口 | `FocusManager.SetFocusedControl(ctrl)` 唯一写焦点入口（点击/Tab/初始全走此）：旧控件失焦镜像 → 新控件聚焦镜像 → `ImeBridge.OnKeyboardFocusChanged` → 失效重绘 |
| 键盘路由 | `KeyboardRouter.OnKey/OnText` 按焦点类型分发；`TextBox` 只读判断在内核（TextBoxModel）层，平台层不判 |
| 点击 TextBox | 单通道 `rt_ui_dispatch_input_activated(elem, localDipX)` → 聚焦 + caret 定位一次完成，禁 focus/click 双通道拼装 |
| 文本编辑真值 | `TextBoxModel` 内核唯一编辑真相：选区只存 `anchor + caret`（active 端）双真值；`SelectionStart/SelectionLength` 为派生计算属性；编辑操作统一先消费选区（替换/删除）再执行默认动作；撤销（快照 + 输入合并）/MaxLength/IsReadOnly 内建裁决 |
| 命中测试 | 前缀宽度按 `version` 缓存于内核度量侧，点击定位 O(log n)/O(1) 查表，替代逐前缀重测 |
| 光标闪烁 | 全局相位（单焦点约束下共享），`IsFocused` 镜像控制绘制；几何常量（文本原点内边距等）单点定义于 `InputMetrics`，渲染端与命中端同源引用 |
| IME 面 | 组字/commit/候选沿 `rt_ui_ime_dispatch` 专用通道；`ImeBridge` 收缩为 IME 专用桥（不含编辑命令 kind）；组字 overlay 不进 `Text`，commit 入内核为独立撤销单元 |
| 诚实边界 | Draft → 契约化修订：M-focus 固定 8 槽注册表为已废弃设计（容量静默丢弃致焦点系统失效，见 plan 输入栈重构节）；文本编辑面首版单行（`TextBox`），多行/剪贴板/覆盖模式不在本契约（见 [text-editing](037-ui/references/text-editing.md) 非目标） |

### 9. 自定义字体（WPF 对齐最小面）

UI 文本字体走**命名族**正道（对标 WPF `FontFamily` 心智，**不必**一次交付 pack URI 全集）。细节见 [custom-fonts](037-ui/references/custom-fonts.md)。

| 面 | 决策 |
|----|------|
| 注册 | `Application.Fonts`（`FontManager`）：`RegisterFamily(name, relativePath)` / 带 Bold 面重载；成功 `true`、失败 `false`，**禁静默骗成功** |
| 消费 | markup / DP：`FontFamily`（族名，非路径）、`FontSize`、`FontWeight`（本 Sprint 至少 `Normal`/`Bold` 换面） |
| 路径 | 相对 app/project base；构建须保证 `bin/<config>/` 下相对路径可见（或注册诚实失败） |
| 回退 | 未注册族名 → 默认族（与 `FontFamilyProperty` 默认一致）；不得把未注册名记为已加载 |
| 度量 | 布局与绘制同源 atlas / 同一解析结果 |
| 拒绝 | UI 绑 `Arc.Drawing.Font` 双轨；用户面暴露后端 `chain` 字符串为第二套 API |
| 非目标（本 Sprint） | `pack://…`、HarfBuzz、彩色 emoji、`FontStyle`（**未交付**） |

## 10. AI 原生设计目标（G1–G3）

> AI 原生是 Arc.UI 的出厂设定，非事后补丁。本主题能力子项经 [references/](037-ui/references/index.md) 的 ai-native-* 系列渐进披露；本节约架构级表述。

### 10.1 三条目标

| # | 目标 | 含义 | 判定 |
|---|------|------|------|
| G1 | **所见即所得（WYSIWYG）** | 设计时与运行时几乎一致的呈现效果 | 同一 spec 在 LivePreviewHost 与 WindowHost 下渲染一致（宿主差异除外） |
| G2 | **生成即见（Instant Preview）** | 生成 ARML/spec 即见效果，无需编译-运行；截图可回喂 LLM；改属性即见表现 | spec 到可见帧无编译、无运行期宿主；补丁到新帧单帧重渲染 |
| G3 | **渲染面即对接面** | 渲染产物是一等公民：PNG 供 LLM/CI，纹理经 VideoSurface 嵌入运行界面 | 预览、评审、运行同一渲染面 |

### 10.2 核心机制总览

| 机制 | 服务目标 | 载体 |
|------|---------|------|
| 双宿主渲染（同一代码路径，PreviewHost / WindowHost） | G1 | VisualHost 演化 + 离屏 target |
| 即时预览（无窗口渲染 + 单帧重渲染 + 属性补丁） | G2 | LivePreviewHost |
| 渲染回读（离屏帧 → RGBA → PNG） | G1/G2/G3 | IRender.CaptureFrame / ReadbackPixels / EncodePng |
| 布局快照（结构化布局树 + 文本度量） | G1/G2 | GetLayoutSnapshot |
| token 目录 + 无裸值校验 | 保真 | DesignTokenCatalog + arc-ui typeck 扩展 |
| 组件 Golden 基准 | 保真 | ui-goldens/ 资产 + 属性 schema |
| 保真闭环（生成→渲染→审视→修正） | G2 | 审视回路 + 验收协议 |
| 多模态输入管线（图 → UI 语义 → spec） | G2 | 版面解析 + 组件识别 |
| 人审固化（动态 → 静态 ARML 晋升） | G2 | ExportArml |

### 10.3 定位与原则

| 面 | 决策 | 拒绝 |
|----|------|------|
| 能力定位 | 渲染回读、布局快照、即时预览、保真闭环为一等能力，与静态 ARML 产品面并列 | 事后「AI 适配层」、外部脚本拼装截图 |
| 渲染面 | 一个渲染面、一个布局引擎、多个宿主 | 设计时软件绘制 / 运行时 wgpu 的双渲染面；HTML/WebView 预览后端 |
| 动态内容 | 动态 UI 是**数据**不是代码；渲染面零业务逻辑；动作经能力门闩 | 动态 UI 携带可执行逻辑进渲染面 |
| 感知成本 | 截图/度量按需渐进披露（先布局快照文本、必要时才截图） | 每次生成全量灌截图 |
| 纪律 | 不碰冻结面（语言核心 / rt_* ABI / std/Arc Stable）；宣称须经验收协议（对齐 RFC 036）；单 M · 子集边界 · 不自动开干 | 静默降级 / 未验收宣称 |

## 边界

- **语言级泛型 / 表达式树 / 可空与绑定机制**见 [011](011-expression-trees-query.md) / [012](012-compile-time-metaprogramming.md)；本 RFC 只讲 UI 框架消费方式。
- **GPU 渲染 / wgpu 后端**属本框架内部实现，不另立主题。
- **主题资源分层 / 编译期扁平化**见本 RFC §4；不拆分独立主题文档。
- **图像与图形 API**（`Arc.Drawing`、二维码、条码）见 [029](029-imaging-graphics.md)；渲染后端见本 RFC。**UI 自定义字体**见本 RFC §9 / [custom-fonts](037-ui/references/custom-fonts.md)；与 `Arc.Drawing.Font` 分轨、禁双绑。**颜色分轨（同字体分轨原则）**：`Arc.UI.Media.Color`（场景色：RGBA 0–1 float，渲染/主题/插值唯一类型）与 `Arc.Drawing.RgbColor`（像素色：byte ARGB，图像 ABI 唯一类型）为两个正交值类型——UI 帧内渲染与主题禁绑 `Arc.Drawing.RgbColor`，图像/位图（Bitmap/QR/Barcode）禁绑 `Arc.UI.Media.Color`；跨轨颜色传递仅允许显式转换（如 ARGB-32 打包），禁隐式双源。
- **显式装配机制**（工具 / DI / Web 端点 / UI）见本 RFC §6；具体领域装配见 038/039/040。
- **AI 原生能力**（即时预览 / 渲染回读 / 保真闭环 / 多模态管线 / VisualHost 演进）见本 RFC §10 与 [references/](037-ui/references/index.md) 的 ai-native-* 系列；与 038 会话/HITL、041 多模态、034 渐进披露衔接，禁双轨。
