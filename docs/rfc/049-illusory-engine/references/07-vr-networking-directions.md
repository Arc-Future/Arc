# 07 VR 与网络方向预留

> 所属：[RFC 049 Illusory 游戏引擎(../../049-illusory-engine.md)。本文是文档链终环，只做**方向登记**：VR 高频姿态、输入语义化、网络预测/回滚如何依托既有确定性核心向前推进。**不预建实现**，M5/M6+ 再硬化细案。
>
> 前置依赖：[01 章程与能力全景](01-charter-capability.md) · [04 仿真核心](04-simulation-core.md)。

## 1. 本环节点：只登记不预建

本环不写实现性契约，只回答两件事：**确定性核心（[04](04-simulation-core.md)）是否足以托起 VR/网络，缺口在哪、如何处理**。能力缺口登记见 [01 §7](01-charter-capability.md#7-能力缺口登记)，本环给出方向性策略。

## 2. 依托的既有能力

VR 与网络成败压在一个地基：**`SimulationTick`** **是唯一时间源、可回放、可预测**（[04 §2](04-simulation-core.md#2-simulationtick唯一时间源)）。由此衍生：

- 行为推进绑定步印（[05](05-behavior-model.md)）→ 网络侧可按步回放对方行为。

- 动画求值绑定步印（[06 §5](06-skeletal-animation.md)）→ 高频姿态可插值到渲染相位。

## 3. 高频姿态（VR view）

- **仿真不放大到头显刷新率**：头显驱动（90/120Hz）不逐帧进仿真，而是在渲染相位按 `CurrentTick` 在**已推进仿真状态**之间插值（tick 定态、渲染插值）。

- 目标：仿真固定步高、行为/物理确定性不变，头显看到的是姿态插值而非再算一轮仿真。

- 姿态插值沿用 [06 §5 求值](06-skeletal-animation.md#5-骨架求值管线求值层) 的时钟口径，同侪复用。

## 4. 输入语义化

- 把**物理输入动作 → 语义动作**（抬 / 挥 / 抓取 / 遥杆位移），供行为层消费；不把设备原始上报直接喂逻辑。

- 语义动作以数据驱动模板登记（结合 [01 §7 输入抽象缺口](01-charter-capability.md#7-能力缺口登记)），M5 前仅登记入口，不建实现。

## 5. 网络预测 / 回滚

- **预测**：本地以 `SimulationTick` 前进；对未确认输入先按预测步推进。

- **回滚/重放**：收到权威快照后，把 `CurrentTick` 回退到快照步，按步重新推进到当前——因一切决定绑定步印，回放结果确定、可复现。

- 快照以 `Step` 为键（[04 §2](04-simulation-core.md#2-simulationtick唯一时间源)）。

## 6. 后置债务纪律

- M1–M3 不写"为未来 VR / 网络预建的耦合钩子"（[RFC 049 §4 不做清单(../../049-illusory-engine.md#4-不做清单红线)）。

- 本环列出的能力**全部登记、暂不实现**；进入实现前必须回到 [RFC 049 章程(../../049-illusory-engine.md) 与能力缺口登记硬化细案，禁止先于契约堆码。

> **不在此篇**：能力缺口总表见 [01](01-charter-capability.md#7-能力缺口登记)。本环为文档链尽头，无后继编号；后续新能力一律先回 \[01] 与主章程登记。
