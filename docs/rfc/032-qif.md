# RFC 032 质检框架 QIF

## 背景

QIF（Quality Inspection Framework）是 Arc 原生质检体系，覆盖七层测试（单元 / 集成 / E2E / 性能 / 属性 / 快照 / 契约）。核心立场与语言反射决策一致：**Arc 永久剔除反射**，测试发现走编译期 AttributeTable 收集 + GenerateTo/Source Generator 生成 registry（信条「代码即数据」），而非运行时反射扫描。`arc test` 是默认验证入口，也是质量闸门（信条「安全在编译期完成——可证伪质量」）。

## 设计决策

### 1. 测试发现与执行模型

| 项 | 决策 |
|----|------|
| 发现 | 编译期 AttributeTable 收集 + GenerateTo/Source Generator 生成 registry（无反射） |
| 执行 | 合成 `__QifTestHost.Main()` 入口 → 编译为静态可执行文件并运行 |
| 断言 | XUnit 风格 `Assert.*` |
| 串行 | 默认串行 |

`arc test` 对标 `dotnet test`：扫描源码 AST 收集 `[Fact]`/`[Theory]` 测试方法，自动生成 `__QifTestHost.Main()` 入口，完整编译后运行。

### 2. `arc test` 命令

| 选项 | 含义 | 默认 |
|------|------|------|
| `--project <PATH>` | 与 `PROJECT` 等价 | — |
| `-c` / `--configuration <CONFIG>` | 构建配置 `Debug` / `Release` | `Debug` |
| `-r` / `--runtime <RUNTIME>` | 目标运行时标识 | 宿主 triple |
| `-o` / `--output <DIR>` | 输出目录 | `bin/<config>/` |
| `--no-build` | 跳过编译直接运行已有测试二进制 | — |
| `--verbosity <LEVEL>` | 日志级别 | `normal` |
| `--filter <EXPRESSION>` | 过滤测试（全限定名 contains 匹配） | — |
| `--list-tests` | 列出所有测试（不执行） | — |
| `--logger <LOGGER>` | 输出格式 `human` / `json` / `junit` | `human` |
| `--coverage` | 启用覆盖率：编译插桩 → 运行产 `.profraw` → 汇总产 lcov 报告（见 [015 references/coverage](015-llvm-backend/references/coverage.md)） | 关闭 |
| `-g` / `--debug` | 发射 DWARF 5 调试信息 | — |
| `--ani-native-lib <DIR>` | Native 库搜索路径（可重复） | — |
| `--obj-dir <DIR>` | 中间产物目录 | `obj/<config>/` |

```bash
arc test examples/UnitTest                              # 默认验证入口
arc test examples/UnitTest -c Release --filter "AssertTests::Equal"
arc test examples/UnitTest --list-tests
arc test examples/UnitTest --logger junit
```

### 3. 测试特性

| 特性 | 语义 |
|------|------|
| `[Fact]` | 无参测试方法，串行执行 |
| `[Theory]` | 参数化测试方法，配合 `[InlineData]` 提供多组入参 |
| `[Fact] async` | 异步测试方法，经 EventLoop 调度运行 |

```arc
[Fact]
public void EqualPasses() {
    Assert.Equal(2, 1 + 1);
}

[Theory]
[InlineData(1, 2, 3)]
[InlineData(10, 20, 30)]
public void AddWorks(int a, int b, int expected) {
    Assert.Equal(expected, a + b);
}
```

### 4. `Assert.*` 断言面

| 断言 | 语义 |
|------|------|
| `Assert.Equal(expected, actual)` | 值/引用相等 |
| `Assert.True(cond)` / `Assert.False(cond)` | 布尔断言 |
| `Assert.Null(x)` / `Assert.NotNull(x)` | 可空断言 |
| `Assert.Throws<T>(fn)` | 断言抛出指定异常类型 |
| `Assert.All(seq, pred)` | 序列逐元素谓词 |
| `Assert.Any(seq, pred)` | 序列存在满足谓词的元素 |
| `Assert.SequenceEqual(a, b)` | 序列元素级相等 |

### 5. 七层测试

QIF 面向七层测试层级，层间职责递进：

| 层 | 内容 | 面 |
|----|------|-----|
| 单元测试 | 单函数/单类行为，`[Fact]`/`[Theory]` + `Assert.*` | 稳定面 |
| 集成测试 | 跨组件协作 | 不在本设计面内 |
| E2E 测试 | 端到端完整链路 | 不在本设计面内 |
| 性能基准 | 基准/回归 | 不在本设计面内 |
| 属性测试 | 基于性质/随机生成验证 | 不在本设计面内 |
| 快照测试 | 输出快照比对 | 不在本设计面内 |
| 契约测试 | 接口/协议契约验证 | 不在本设计面内 |

### 6. 跳过机制 QIF_SKIP

`QIF_SKIP` 是唯一受认可的跳过标记。默认入口**不允许 Fact-Skip**——回归不靠 Skip 粉饰；唯一允许的 skip 为显式 `QIF_SKIP`。默认入口的通过标准为「零 Fact-Skip」。

### 7. `[qif]` 配置节

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `output` | string | `"obj/qif"` | QIF 产物根目录（`.arcqif` + `report.json` 在此层）；缺省从固定 `obj/` 派生 |
| `emit_json_report` | bool | `true` | 是否生成 JSON 报告 |
| `keep_json_history` | int | `1` | JSON 报告历史保留份数 |
| `persist_results` | bool | `true` | 是否持久化 `.arcqif`（false 仅控制台/JSON） |
| `log_dir` | string | `"{qif.output}/logs"` | 日志目录 |
| `log_keep_history` | int | `10` | 历史日志保留份数（超过自动清理最旧） |
| `log_level` | string | `"info"` | `trace`/`debug`/`info`/`warn`/`error` |
| `output_format` | string | `human` | 报告输出格式（`human`/`json`/`junit`），可被 `--logger` 覆盖 |

字段优先级链：`CLI 参数 > [qif] 字段 > 内置默认值`。

### 8. 拒绝项

| 项 | 裁决 |
|----|------|
| 运行时反射发现测试 | 拒绝——Arc 永久剔除反射，发现走编译期 registry |
| 默认并行 | 拒绝——默认串行保证确定性；并行不在本设计面内 |
| 测试作为可选旁路 | 拒绝——`arc test` 是默认验证入口与质量闸门 |

### 9. 覆盖率（与 QIF 正交）

覆盖率是**编译/运行层能力**（codegen 插桩），与本框架（测试发现/执行）正交：QIF 负责「跑哪些测试」，覆盖率负责「跑完之后哪些行被触及」。`arc test --coverage` 是串联点——`arc test` 既触发 QIF 执行，又（可选）触发插桩与汇总产 lcov 报告。插桩机制、报告格式（lcov 主 / cobertura 扩展）、验收标准与非目标见 [015 references/coverage](015-llvm-backend/references/coverage.md)；覆盖阈值门禁由消费方（std 量产门禁 / DoD）另立。

## 边界

- **编译器管线**（attr 收集、GenerateTo、合成入口 lower）见 [013](013-compiler-pipeline.md)；本 RFC 只讲 `arc test` 用户面、断言与配置。
- **QIF 产物配置**以章节 [17 arc.toml 项目清单](../user-guide/17-arc-toml-reference.md) 为权威。
- **动态测试 host**（测试项目编译为动态库经 `arc-test-host` 加载）、`DI`/fixture 生命周期不在本设计面内。
- **覆盖率**（`arc test --coverage` 的机制与格式）见 [015 references/coverage](015-llvm-backend/references/coverage.md)。
