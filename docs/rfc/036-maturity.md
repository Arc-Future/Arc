# RFC 036 成熟度与基础面稳定

## 背景

Arc 以**可证伪协议**治理成熟度：「Arc 底座真实可靠、性能优异」立宪为可证伪验收目标。四项硬约束：**三硬要求**（底层彻底稳定 · 极致性能 · 高阶可编译）、**基础面冻结**（语言核心 / `rt_*` ABI / `std/Arc` Stable 默认冻结）、**宣称纪律**（未经验收不得宣称）、**性能门禁协议**（热路径同机成对对照）。「业界领先 / 碾压 / 超越」不是一刀切禁用，而是「未经验收协议不得宣称、验收通过后由维护者书面宣布方可声明」。

`unsafe` 永久拒绝、用户面指针与 lifetime 标注永久拒绝。

## 设计决策

### 1. 三硬要求

| 硬要求 | 含义 |
|--------|------|
| H1 底层稳定 | 默认入口零 Fact-Skip、回归不靠 Skip 粉饰（见 [032](032-qif.md) QIF_SKIP） |
| H2 极致性能 | 热路径同机成对对照不劣化并达阈值（见 §2 协议） |
| H3 高阶可编译 | 高阶代表性套件可编译并完整物化 |

三硬齐备是后续能力解锁的可靠前提；基础面仍守 §3 冻结。

### 2. 热路径对照协议（H2）

| 项 | 规则 |
|----|------|
| 脚本 | `scripts/bench/run-std-hotpath-h2-gate.ps1` |
| 成对 | `r_i = Arc_ns/op ÷ base_ns/op`（同 pass 紧挨执行） |
| n | 11；warmup 各 1 次不计 |
| 尖峰 | 2× 中位剔除；剩 `k ≥ 7` |
| 阈值 | 各场景 gate = raw 中位 **≤ 0.85×** 方可通过 |
| 禁 | 手工删点 / 只报安静子集 / ratio-of-medians 冒充成对中位 |

**C 生态利用度门禁**：C 化必须以可证伪性能门禁（或安全/正确性驱动）为前置——有门禁证据的面方可因性能引入 C 生态；无门禁的面不因「性能诱惑」C 化（先留 Arc，立门禁后再评估）。C 生态利用仅发生在 runtime 层（`crates/runtime/` 及各 vendored 底座目录），编译器核心 crate 禁领域能力（架构红线）。

| 面 | 门禁/证据 | C 化裁决 |
|----|----------|---------|
| 集合（List/Dict/HashSet/Concurrent） | H2 协议窗证据 | 采用 C（薄封装，以门禁续证） |
| SIMD / Vector / Math | 结构性优势场景 harness（SoA 不慢于 AoS） | 编译器直射 LLVM intrinsic/SIMD，不引 C |
| 密码学 / TLS | 安全/正确性驱动，成熟库优先 | vendored 成熟库 |
| JSON | 无性能门禁 | 不 C 化；引 C tokenizer 须先立 JSON 性能门禁 |
| gzip/deflate 压缩 | 无性能门禁 | 不 C 化（触发式，需求出现后再评估） |
| DI 容器 | 实证 C 无收益 | 保持纯 Arc |
| LINQ/表达式树/序列化 | 无门禁 + 架构红线 | 保持纯 Arc |

**增量构建门禁协议**：增量编译粒度提升属性能面变更，先立可证伪门禁（「无门禁不改性能面」）。本协议与热路径对照协议（上表）并列，覆盖**开发内环（inner loop）**。基线为「全量冷构建」自身（非成对 base），故以「冷构建 vs 增量重建」wall-clock 比率度量，另加一条正确性等价子门禁。缓存机制与增量粒度落点见 [031 §6](031-compiler-cli.md)。

| 项 | 规则 |
|----|------|
| 脚本 | `scripts/bench/run-incremental-build-gate.ps1`（实现期交付） |
| 夹具 | 新建代表性多项目解决方案 `target/e2e/incremental-gate/`（**不复用** `examples/`）：≥ 10 个 path 依赖项目，含「叶子库 → 中间库 → 入口」依赖链 + 若干扇出项目；每项目 ≥ 3 个 `.as` 文件且 codegen 非平凡（避免被常量折叠成空链接） |
| 冷构建 | 清空各项目 `obj/`/`bin/` 后 `arc build`，计 wall-clock `T_cold` |
| 增量重建 | 对单一叶子库内一个文件做一行内容替换（不改文件名、不增删文件、不改 `arc.toml`），`arc build`，计 `T_incr` |
| 指标 | ① 加速比 `s = median(T_incr) / median(T_cold)`；② 脏闭包占比 `d = 本次重编 .as 文件数 ÷ 总 .as 文件数`（须经 `--incremental-report` 仪表化暴露，仪表化为门禁前置交付物） |
| n | 冷构建 5 次、增量重建 7 次；各 warmup 1 次不计 |
| 尖峰 | 2× 中位剔除；增量重建剩 `k ≥ 5`、冷构建剩 `k ≥ 3`，否则判协议无效重测 |
| 阈值 | 增量重建中位 **≤ 0.50×** 冷构建中位（`s ≤ 0.50`），**且** `d ≤ 0.25`（单叶子文件变更不得重编未触达项目） |
| 禁 | 手工删点 / 只报安静子集 / 以「无 output 重链接」冒充真增量（必须真实跳过 parse/typeck/codegen，不得仅跳过 link）/ `ratio-of-means` 冒充成对中位 / 用 `--no-build` 规避编译 |

**正确性等价子门禁**（stale-cache correctness）：增量产物须与全量产物行为等价，否则性能收益无效。

| 项 | 规则 |
|----|------|
| 等价断言 | 冷构建产物与增量重建产物跑同一套 QIF/回归套件（[032](032-qif.md)），断言退出码与断言结果一致 |
| 确定性首选 | 产物可做到 **bit-identical**（同输入同字节）则优先断言字节等价（**主口径**）；若存在内嵌时间戳等非确定字节，退化为「测试套件等价 + 产物尺寸 / 符号集一致」并记录退化原因（两者均记录） |
| 反例矩阵 | 依次变更「叶子源码 / 中间库源码 / `arc.toml` / `path` 依赖内容 / 工具链重编」各一次，断言均触发对应脏闭包重建、产物更新 |

**通过判据**：`s ≤ 0.50` 且 `d ≤ 0.25` 同时达标 **且** 正确性等价 + 反例矩阵全绿；任一条不满足即判未通过，不得宣称增量收益，回退当前保守全量指纹。宣称纪律沿用 §4。

### 3. 基础面冻结

| 稳定面 | 范围 |
|--------|------|
| 语言核心语法 | 已接受 RFC 锁定的语法表面 |
| runtime ABI | `rt_*` 符号、布局与调用约定 |
| `std/Arc` Stable | 文档与实现已标 Stable 的公开 API |

- 破坏性变更 → **先 RFC**，再同变更集改代码与文档。
- 修 bug/perf 优先**不改公开契约**。
- 新增 ABI 符号经独立立宪可行，C 生态新增不破坏基础面冻结。

### 4. 宣称纪律

「业界领先 / 碾压 / 超越」可声明，但须满足全部前置条件：

| 条款 | 内容 |
|------|------|
| 声明前置条件 | ① 对应场景通过可证伪验收协议（整协议绿）；② 声明窗记录版本标识；③ 维护复测期（默认连续 ≥20 次协议绿）无回归 |
| 宣布主体 | 仅维护者书面宣布，并记录声明窗版本标识 |
| 撤回机制 | 已声明场景后续回归（复测不绿）→ 声明自动失效，修复后再宣布 |
| 不宣称 | C# 完备对等（独立条款，不变更） |

「不得宣称」的替代：**未经验收协议不得宣称；验收通过后可声明，声明须引用协议窗版本**。

### 5. 借用安全基线（至少 Rust/C# 级）

| 安全面 | 编译期保证 | 运行时保证 |
|--------|-----------|-----------|
| 内存安全 | 无 UAF / double-free / 空引用解引用 + NLL | ARC 归零即回收；无 STW |
| 数据竞争 | NLL 可变/共享借用排他 | 原子 refcount |
| 迭代器失效 | NLL 检测 | — |
| Span 逃逸 | `E_SPAN_ESCAPE` | — |
| 循环泄漏 | — | 循环收集器 + `Weak<T>` 手动断环 |

NLL **无条件启用**；循环收集默认 always-on（阈值触发、用户无感）。此为本成熟度宪章的一部分，属设计契约。

### 6. 拒绝项

| 项 | 裁决 |
|----|------|
| 无对照 / 未经验收的「业界领先 / 碾压 / 超越」宣称 | 拒绝——须整协议绿 + 维护者宣布 |
| 宣称 C# 完备对等 | 拒绝——独立条款不变 |
| `unsafe` 用户面 / 标杆 std API | 拒绝——性能以 Verified FFI + 安全 Span + 单态/内联达成 |
| 用户面指针 / `'a` lifetime / `Borrow<T>` 一等类型 | 拒绝 |
| 循环收集器用户开关 | 拒绝——默认 always-on，无开启/关闭途径 |
