# RFC 042 P2P 网络（Arc.Net.P2P）

## 背景

`Arc.Net.P2P` 是 Arc 的**点对点网络**领域：传输/协商/DHT/NAT/中继/PubSub + 稳定性突破。协议层（身份/地址/协商/发现/DHT/gossipsub/中继/NAT/资源管理）**必须纯 Arc 实现**；密码学/传输热路径复用既有 C 底座。本领域与推理引擎（`Arc.AI`，见 [041](041-ai-inference.md)）互不依赖。

## 设计决策

### 1. 定位与技术路线

`Arc.Net.P2P` 对标 libp2p 成熟能力面，走**方案 A（纯 Arc 协议层）为主体 + 方案 C（成熟 C 底座）为加速器**；方案 B（rust-libp2p 经 C ABI 封装）明确拒绝（架构红线 + tokio 运行时信条冲突）。

| 能力面 | 决策 |
|--------|------|
| 传输 | TCP + yamux 流复用 + multistream-select + QUIC（ngtcp2/TLS-over-QUIC）+ WebSocket |
| 安全 | Noise XX（libp2p prologue）+ TLS 1.3；Secio 不实现（废弃） |
| 身份 | PeerId（multihash/multibase/base58btc）+ Multiaddr + 多密钥（Ed25519 默认/RSA/secp256k1）+ SignedEnvelope/PeerRecord |
| 发现 | mDNS + Kademlia DHT（peer/content routing · provider records · bootstrap） |
| NAT | STUN/TURN/ICE + AutoNAT + DCUtR 打洞 |
| 中继 | Circuit Relay v2（hop/stop）+ 自动中继 |
| PubSub | gossipsub v1.1（mesh + 验证器 + peer scoring + PX） |
| 治理 | ConnManager + Resource Manager（作用域限制 + per-IP 限连）+ 拨号治理 |

协议层纯 Arc、零新 ABI 居多；`rt_*` ABI 逐项独立立宪（`rt_noise_*` 扩展 XX、`rt_kad_*` 桶表、`rt_socket_*` 数据报）。每能力面以**互操作级验收**（与 go-libp2p/rust-libp2p/dotnet-libp2p 本地节点或官方向量）为准——本地闭环绿 ≠ 生态互操作；未完成互操作级验收不得宣称「已达 libp2p 级」。

### 2. 稳定性突破（超越 ≠ 豁免及格）

在 parity 之上叠加六大突破方向，解决 libp2p 结构性未解缺陷（DHT 冷启动鸡生蛋、抖动下路由表陈旧、NAT 穿透概率性、Sybil/Eclipse 隔离、评分可绕过、基础设施重中心化）：

| 方向 | 突破内容 | 量化指标（可证伪验收） |
|------|---------|------------------------|
| A 确定性自适应 DHT | churn 感知自适应 k-bucket + 查找一致性 + 抗 Sybil 区域查询 | churn 查找成功率 ≥99%；一致性 ≥90% |
| B QUIC-first 确定性 NAT 穿越 | 主动探测 + 中继回退 + 路径监测 + QUIC 连接迁移 + 去中心化协调 | 直连成功率 ≥90%；建立 ≤200ms；恢复 ≤100ms |
| C 无中心引导冷启动 | mDNS + DNS-over-DHT + 可验证匿名引导（去硬编码 bootstrap） | 零预配置 N 秒加入 |
| D 编译期验证协议 | 「协议即类型」：声明式协议 + 编译期状态机/超时/重放/签名链校验 | 恶意策略经合法类型检查不可达 |
| E Eclipse 免疫对抗路由 | Constrained Routing Table + 匿名审计 + DHT 全链路签名 peer record | 任意恶意比例下不被隔离 |
| F 确定性资源治理 | 可证边界拨号治理 + 资源管理可证上界 | 高并发下资源可证上界 |

「超越 ≠ 豁免及格」：所有突破在互操作级验收之上叠加；未完成「互操作 + 稳定性量化」双验收不得宣称突破。方向 D 为语言级能力（协议 DSL / 编译期校验走独立语言 RFC），不直接改编译器核心。

### 3. 拒绝项

| 项 | 裁决 |
|----|------|
| rust-libp2p 经 C ABI 封装（方案 B） | 拒绝——架构红线 + tokio 运行时信条冲突 |
| 整库采用 c-libp2p | 拒绝——年轻、成熟度不足；组件级引入亦暂不启动 |
| 浏览器传输面（WebTransport/WebRTC） | 不在本设计面内——桌面 AOT 优先 |
| 宣称「已实现 / 已达 go-libp2p 级」 | 拒绝——互操作级验收完成前禁宣称 |
| NAT 端口映射（UPnP/PCP）、DHT 可观测仪表板 | 不在本设计面内 |
