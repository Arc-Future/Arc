# RFC 040 Web 框架与 SSR

## 背景

Arc.Web 是 Arc 的轻量云服务框架：以**单宿主 `WebApplication`** 装配服务、以**内置 IMediator** 承载请求处理、以**特性自动路由**把 `IRequest` 即端点、以 **SSR 声明式 HTML** 输出网站、以 **`IWebResult`** 提供多态页面结果、以 **gRPC 集成层**接入 `Arc.Net.Grpc`。它抛弃 ASP.NET Core 体系糟粕（中间件/过滤器双轨、控制器、`HttpContext` 上帝对象、`IOptions` 间接层、程序集扫描、Startup 仪式、minimal/controller 双轨），走**单一惯用法**——同一机制一条正道。

网络协议层（HTTP/TCP/WebSocket/QUIC）见 [025](025-networking.md)；本 RFC 只讲 `Arc.Web` 框架装配与网站能力。

## 设计决策

### 1. 分层架构

| 层 | 命名空间 | 职责 | 依赖 |
|----|----------|------|------|
| Core 宿主 | `Arc.Web` | `WebApplication` + IMediator + 路由 + 绑定 + 动态鉴权 + 配置 | `Arc.Net` · `std/DI` · `Arc.Text.Json` |
| gRPC 集成 | `Arc.Web.Grpc` | 把 `Arc.Net.Grpc` 核心挂进宿主，unary → `SendAsync` | `Arc.Web` · `Arc.Net.Grpc` |
| SignalR 集成 | `Arc.Web.SignalR` | 基于 WebSocket 实时通信 | `Arc.Web` · `Arc.Net` |
| 扩展点 | `Arc.Web.*` | 更多领域扩展 | — |

gRPC 核心留在 `Arc.Net.Grpc`（与宿主解耦），`Arc.Web.Grpc` 仅集成适配层；`Arc.Web` 不反向依赖 gRPC/SignalR（后者作扩展挂接点接入）。纯 Arc 实现，无 vendored Kestrel/C# 桥。

### 2. 宿主与装配（WebApplication）

```as
var app = new WebApplication();
app.AddServices(services => { ... });   // 复用 std/DI，仅注册领域服务
await app.RunAsync();                    // 框架默认自动装配端点/配置/鉴权行为
```

| 面 | 决策 |
|----|------|
| 宿主 | 单一 `WebApplication`，一次性装配即启动（无 builder/Startup 仪式） |
| 配置 | 框架默认 `IConfiguration` 自动解析 `app.json`，`Get<T>()` 强类型反序列化；**砍 `IOptions` 间接层** |
| DI | 复用 `std/DI`，宿主内建每请求作用域 |
| 自动装配 | 端点/处理器/配置/鉴权行为由框架默认完成，开发者零样板 |
| 显式注册 | `MapGet<TReq,TResp>(template[, roles])` / `MapPost` / `MapPut` / `MapDelete` / `MapPatch` —— 与 `[Get]/[Post]/[Put]/[Delete]/[Patch]` 特性声明等价的两条注册路径（同一端点面，单一惯用法） |
| 路由语义 | 路径不存在 → **404**；路径存在但 HTTP 方法未注册 → **405 Method Not Allowed**（REST 语义，`EndpointRegistry.MatchAnyMethod` 区分）；未注册动词在已存在路径上不得回退 404 |
| 传输 | 服务 HTTP/1.1（`Arc.Net` 底座）；HTTP/2/3 服务端不在本设计面内（依赖服务端 TLS + ALPN 版本协商），不宣称 |
| 并发模型 | 每监听端点一个 accept 线程（同步 accept，非瓶颈）；**连接处理经默认线程池**（`Task.Run`：CPU 核数 worker + 共享任务队列，线程复用——并发连接数可远大于线程数，消除 thread-per-connection 的线程爆炸与每连接建/销线程开销，遵循 RFC 009 调度器「最简稳定 · 不引入 work-stealing」纪律）；**有界并发背压**（`MaxConcurrentConnections`，默认 256，对齐 Kestrel Limits.MaxConcurrentConnections，`RunAsync` 启动时固化）：在途槽位计数信号量非阻塞获取（`Wait(0)`），满则新连接立即关闭（背压拒绝，不排队）；服务完成经 finally 恒归还槽位；**每请求独立作用域**（`rootSp.CreateScope()`），请求路径结束（含异常/404/405 分支）统一 `scope.Dispose()`；作用域不跨请求共享 |
| 并发诚实边界 | 传输原语为同步阻塞面（`Http11ServerConnection` 同步读，带 30s 超时）——慢连接占用池 worker，由有界上限（默认 256）保护总量；连接处理内的同步桥（`authTask.Wait()` / `task.Result`）在池 worker 上自 poll，不依赖 EventLoop；Reactor 全链异步化（零阻塞 worker）为后续专项，未落地前不宣称零线程连接面 |
| 生命周期契约 | 容器与作用域是**缓存持有者**：对缓存实例（Singleton/Scoped），`GetService`/`GetKeyedService`/`GetServices` **不得裸返回内部引用**——须经中间局部赋值（拷贝 inc）转新引用后返回，调用方 dec 与容器持有各自独立、计数平衡（裸返回借用 + 调用方 dec 会使缓存计数漂移 → 提前 free → 悬垂 dec）；`Task<T>.Result` 同步提取返回强持有（结果所有权契约见 RFC 009） |
| 并发正确性验收 | 并发压力循环（N 路并行 × 多轮，含 32 路高并发）全部返回正确响应、零 panic、零 UAF；有界并发场景（上限 K + 慢 handler + K+8 并发 → 恰 K 成功、8 拒绝、服务端零 panic）为宿主并发能力宣称的验收协议 |

### 3. IRequest 即端点 + 内置 IMediator

```as
[Get("/api/users/{id}")]
public class GetUserRequest : IRequest<UserDto> {
    public int Id;
}
public class GetUserHandler : IRequestHandler<GetUserRequest, UserDto> {
    public async Task<UserDto> Handle(GetUserRequest request) { ... }
}
```

| 面 | 决策 |
|----|------|
| 端点声明 | `[Get]/[Post]/[Put]/[Delete]/[Patch]` 特性自描述路由，路由 + 方法 + 绑定集中在类型上 |
| IMediator | 接口泛型方法 `SendAsync<TReq,TResp>`（单 handler · `Task<TResponse>`）+ `PublishAsync<TNotif>`（多 handler）；泛型分发不依赖静态扩展（mediator generic-dispatch verdict (internal proposal)） |
| 横切面 | **唯一** `IPipelineBehavior` 管道（合并中间件/过滤器双轨） |
| 绑定约定 | 路径 `{id}` → 同名标量；GET/DELETE 查询串 → 同名属性；POST/PUT/PATCH body → `Arc.Text.Json` 反序列化（PATCH 与 PUT 同走 body 绑定，`[Patch]`/`MapPatch` 端点不落入路径参数分支） |
| 请求上下文 | 收窄为显式 `RequestContext`（无 `HttpContext` 上帝对象/`IHttpContextAccessor`） |

无控制器、纯 handler 函数；`IRequest` 即端点，`minimal/controller` 双轨收敛为单一路径。

### 4. 鉴权

| 面 | 决策 |
|----|------|
| 标记 | `[Authorize]` 鉴权标记 |
| 行为 | `IAuthorizationBehavior` 可扩展鉴权行为（默认角色鉴权，可扩展动态鉴权/DB 支撑） |
| 认证方 | 默认不内置认证方；token/cookie → principal 认证面可插拔 |
| 校验 | 走 `IPipelineBehavior`（无 `DataAnnotations`/`ModelState`/`[ApiController]` 自动 400 耦合） |

### 5. SSR 声明式 HTML

网站开发采用 **WPF xaml+cs 心智模型**：页面标记 = 标准 HTML 文件 + code-behind = `PageHandler` 基类 + DataContext = 强类型模型。模板语法为**三标记绑定模型**：`{{ }}` 文本插值 · `attr={ }` 属性绑定 · `a-` 短前缀指令（`a-for`/`a-if`/`a-html`）。

```html
<!-- 页面标记 home.html = 标准 HTML + 三标记绑定 -->
<main>
  <h1>{{Title}}</h1>
  <ul>
    <li a-for={post in Posts}>
      <a href={post.Slug}>{{post.Title}}</a>
      <time>{{post.PublishedAt}}</time>
    </li>
  </ul>
  <p a-if={Empty}>暂无文章</p>
  <div a-html={IntroHtml}></div>
</main>
```

```as
[Get("/")]
public class HomePage : IRequest<IWebResult> { }
public class HomePageHandler : PageHandler<HomePage> {
    public override async Task<IWebResult> Handle(HomePage request) {
        var posts = await mediator.SendAsync(new ListPostsQuery());
        return View(new HomeModel { Title = "Arc Blog", Posts = posts, Empty = posts.Count == 0 });
    }
}
```

| 形式 | 形态 | 安全 |
|------|------|------|
| 文本插值 | `{{Property}}` | 默认转义 |
| 属性绑定 | `attr={Property}` | 默认转义（上下文感知） |
| 原始 HTML | `a-html={Property}` | 显式退出 |
| 循环 / 条件 | `a-for={x in Xs}` / `a-if={B}` | — |

绑定 = 属性路径（WPF 思路），复杂逻辑在模型预计算，模板无任意表达式/语句；绑定路径**编译期对照模型类型解析**（绑错即编译期报错）。框架默认安全转义（对齐 Go `html/template` 上下文感知），XSS 由框架兜底。

`IWebResult` 多态结果族：`IHtmlView`（视图）/`IRedirectResult`（重定向，PRG）/`IFileResult`（文件/二进制）。`PageHandler` 提供 `View(T)`/`Partial(T)`/`Redirect(url)`/`File(data, contentType)`。HTML 页面与 JSON API 走同一条 `IMediator`/`IPipelineBehavior`/DI 管道（`IRequest<IWebResult>` 作扩展响应类型），不引入第二套请求面。

支持组件/Layout 标记级片段复用、表单往返校验回显、会话态（cookie 面）、流式 TTFB、基础静态资源服务（MIME + 缓存头）、部分内容响应（206 Partial Content / Range 按需切片）。

SSR 片段复用走**两个职责清晰的标记级原语**，对齐 Web Components `<slot>` / Vue 插槽 / kilnx 片段槽的标准做法；命名统一为显式 `name` 属性（废除"首个属性当槽名"的位置式写法）。**实现细节与 Vue 插槽对标见 [SSR 多槽能力 · 实现细节与 Vue 对标](040-web/references/ssr-slots.md)。**

**包裹原语 `<a-layout>` + 单 `body` 注入。** 页面端点渲染一整块 HTML，被指定布局包裹、注入唯一 `body` 槽（对标 Razor `@RenderBody()`）。页面只产一块内容、天然单注入点——**多槽在页面↔布局间无意义，布局不承担多内容区职责**；多槽属于组件封装（见下），此为诚实边界。

```html
<!-- _layout.html：外层骨架 + 唯一 body 注入点 -->
<header class="site">...</header>
<nav>...</nav>
<a-slot name="body" />
<footer>© 2026 Arc SSR</footer>
```

页面经 `<a-layout name="AppLayout" />` 声明关联；布局编译为 `__SsrLayout_{Name}.Render(string body)` 复用单元（1-N）。

**封装原语 `<a-component>`：默认槽 + 具名槽。** 对标 Web Components 影子 DOM `<slot>` / Vue 插槽：可复用封装（外框固定、内容由调用方注入）。组件模板内部以 `<a-slot name="...">` 声明占位（可带 fallback 内容）；调用方用全局属性 `slot="name"` 标记子元素填充，无 `slot` 属性的子内容进默认插槽。

```html
<!-- card.html：组件模板，外框 + 三个具名槽 -->
<div class="card">
  <header><a-slot name="header">Default Title</a-slot></header>
  <main><a-slot name="body" /></main>
  <footer><a-slot name="footer" /></footer>
</div>
```

```html
<!-- 调用方：按名注入内容；<badge/> 无 slot 属性 → 默认插槽 -->
<a-component path="card" source={Card}>
  <h1 slot="header">{{Card.Title}}</h1>
  <p slot="body">{{Card.Summary}}</p>
  <a-component path="badge" source={Card.Tag} />
</a-component>
```

构成 `__SsrComponent_{path}` 渲染类，`Render(payload, header, body, footer)`——payload + 按槽名确定性展开的具名参数。一次编译、1-N 复用。

组件语义（对齐标准）：
- **槽体在调用方作用域渲染**（Vue/kilnx 语义，插槽内容访问父作用域）；`source` payload 在组件模板作用域解析。二者互补：`source` 供数据（菜单/列表数据），槽供标记注入（卡片/外壳任意内容）。
- `name` 唯一；同一组件内重复 `name` 仅首个生效。槽未填充渲染 `<a-slot>` fallback；调用方给了组件未声明的槽 → 编译期报错（诚实边界）。
- **`source` 可选**：缺省时以当前上下文数据为 payload（组件模板级 DataContext，对齐 WPF DataContext 继承语义），便于数据驱动组件无冗余传参。

**诚实边界**：Arc 原生非同构，无客户端运行时/JS 水合，不对标 Next.js；网站定位为「SSR 内容站点 + 前端应用后端」。拒绝 WebForms ViewState/postback、Razor `@` 任意代码混写、服务器控件生命周期、`ViewData`/`ViewBag`/`TempData` 弱类型魔法、模板 DSL 双轨。

### 6. gRPC 集成

`Arc.Web.Grpc` 把 `Arc.Net.Grpc` 核心（HTTP/2 传输、四种调用类型）挂进 `WebApplication`：unary 调用 → `IMediator.SendAsync`，复用同一管道与鉴权。gRPC 核心与宿主解耦、独立可复用；`Arc.Web.Grpc` 仅作集成适配层，不重复实现协议。

## 边界

- **网络协议层**（HTTP/TCP/WebSocket/QUIC、HTTP/1.1/2/3）见 [025](025-networking.md)；本 RFC 只讲 `Arc.Web` 框架装配与 SSR。
- **gRPC 协议核心**（`Arc.Net.Grpc`：HTTP/2 传输、四种调用类型）见 [025](025-networking.md)；本 RFC 只讲 `Arc.Web.Grpc` 集成层。
- **DI 容器 / 配置**见 [023](023-math-tensor-di.md)；本 RFC 只讲宿主装配方式。
- **端点显式注册机制**见 [037 §6](037-ui.md)；本 RFC 只讲 Web 端点装配。
