# RFC 019 自举

## 背景

Arc 的长期目标是**自托管（self-hosting）**——编译器最终用 Arc 源码实现，由当前 Rust 编译器编译出下一代 `arc`。当前编译器以 Rust workspace 实现，仅为 **Phase 0 自举（bootstrap）** 手段：用宿主语言快速验证语义与管线，**不是**将 Arc 定义为 Rust 宏、属性或内嵌 DSL。各编译阶段 crate 保持窄接口与单向依赖，便于逐阶段用 Arc 重写而不改变语言语义。信条④「代码即数据」——编译器也是数据。

**立宪公理**：语言表面扎实稳固是自举前提；**不得为冲自举掩盖语言债**。

## 设计决策

### 1. 阶段划分

| 阶段 | 编译器实现 | 语义 |
|------|------------|------|
| Phase 0 | Rust `crates/*` | 引导实现；验证规范与集成测试，为语言唯一权威 |
| Phase 1+ | Arc 源码（自托管） | Rust 编译器仅作 bootstrap 链一环，逐步退役 |

**单一权威**：自托管未达成前，文档与 RFC 仍为语言唯一权威；Rust 实现不得引入文档未描述的行为。

### 2. 自举门禁

自举推进须满足七类门禁，作为设计验收契约：

| 类别 | 项 |
|------|-----|
| 语义 | S1–S5（语法 / 类型 / 内存 / 异步 / 查询） |
| 里程碑 | M1–M5（成熟度签收） |
| 运行时 | R1–R3（`rt_*` ABI 可被 Arc 调用） |
| 工具链 | T1–T5（构建 / 测试 / 产物） |
| 验证 | V1–V3（e2e / 对照） |
| 文档 | D1–D3（normative 指针） |

### 3. 硬约束

- **禁止删 Rust 词法/parser**——自举未完成前 Rust 引导链不可回退；
- **禁止切默认 CLI**——默认 CLI 保持 Rust 编译器，直至 Arc 编译器等价；
- **单 M · 子集边界 · 不自动开干**——每个里程碑单目标、有明确定义的子集边界，不自动启动下一里程碑。

### 4. 子集边界

自举以**子集**推进：每个里程碑定义明确的语言子集边界（parser 子集、HIR 子集、typeck 子集、codegen 子集），逐层验证等价后再拓宽。子集边界是设计契约，非进度记录。

首个里程碑 M4（parser 子集）的约定边界（纳入产生式、排除表、禁止项、验收名）见 [019-m4-parser-subset.md](019-m4-parser-subset.md)。
