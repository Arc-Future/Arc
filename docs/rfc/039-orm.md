# RFC 039 ORM 与 SQL 翻译

## 背景

Arc.Orm 是 Arc 的对象关系映射层：以**表达式树**承载查询意图、经 **SqlTranslator** 在运行期翻译为 SQL、由**方言 Provider** 适配不同数据库、以**实体物化**把行映射为强类型对象、以**连接管理**统一生命周期。它是纯标准库领域层：编译器只负责表达式树的**编译期构建与类型检查**，翻译逻辑全部由 `Arc.Orm` 在 Arc 语言内实现——编译器核心 7 crate 零领域逻辑。

`Arc.Orm.SQLite` 为方言实现，与 `Arc.Orm` 平级；方言 Provider 遵循平级包/单惯用法，不内嵌编译器。

## 设计决策

### 1. 分层架构

| 层 | 命名空间/包 | 职责 |
|----|-------------|------|
| 查询基座 | `Arc.Linq` / `Arc.Linq.Expressions` | 表达式树构建与查询执行约定 |
| ORM 核心 | `Arc.Orm` | `IQueryProvider`、`SqlTranslator`、实体物化、连接管理、数据读取契约 |
| 方言 | `Arc.Orm.SQLite` | SQLite 方言 Provider（`SqliteProvider`） |
| 更多方言 | `Arc.Orm.<Dialect>` | 平级平铺的方言包（如 `Arc.Orm.Pg` 等） |

**依赖单向**：`Arc.Orm` 依赖 `Arc.Linq`；方言 `Arc.Orm.<Dialect>` 依赖 `Arc.Orm` 与 `Arc.Linq`。方言 Provider 相互平级、互不依赖。

### 2. 表达式树翻译

表达式树在**编译期**构建并经类型检查（机制见 [011](011-expression-trees-query.md)）；`SqlTranslator` 在**运行期**把表达式树翻译为 SQL 与参数列表。

```as
namespace Arc.Orm.SQLite;
using Arc.Linq;
using Arc.Linq.Expressions;
using Arc.Orm;

class SqliteProvider : IQueryProvider {
    public IEnumerable<T> Execute<T>(Expression expression) {
        var (sql, parameters) = SqlTranslator.Translate(expression);
        return ExecuteSql<T>(sql, parameters);
    }
}
```

| 面 | 决策 |
|----|------|
| 树 → SQL | `SqlTranslator.Translate(expression) → (sql, parameters)` |
| 类型安全 | 查询经强类型 `Expression<T>`，编译期校验属性/类型 |
| 参数化 | SQL 与参数分离，规避拼接注入 |
| 拒绝 | 字符串拼接 SQL 作为主路径；SQL 领域逻辑进入编译器核心 |

### 3. 方言 Provider

方言 Provider 实现 `IQueryProvider` 统一契约，翻译差异收敛在方言内；核心 `SqlTranslator` 产出通用翻译骨架，方言补齐语法差异。

| 方言 | 命名空间 | 定位 |
|------|----------|------|
| SQLite | `Arc.Orm.SQLite` | 首方言，本地闭环 e2e 载体 |
| 其余 | `Arc.Orm.<Dialect>` | 平级平铺，按需另立 |

方言包平级、不内嵌编译器、不占 `Arc.Orm` 核心命名空间。开发者经 `Arc.Orm` 统一消费，不感知方言差异（换方言不换查询面）。

### 4. 实体物化

| 面 | 决策 |
|----|------|
| 映射 | `IQueryProvider.Execute<T>` 把行映射为强类型实体 `T` |
| 列映射 | `ColumnAttribute` 等特性声明列名/映射（自动属性，对标 C# 优雅简洁） |
| 读路径 | `IDataReader` 契约承载列读取，实体物化消费之 |
| 拒绝 | 反射运行时映射主路径；动态/无类型结果为主路径 |

### 5. 连接管理

| 面 | 决策 |
|----|------|
| 连接面 | 统一连接管理，生命周期显式（`using`/`IDisposable`） |
| 查询执行 | 经 `IQueryProvider.Execute<T>`，连接/事务边界清晰 |
| 拒绝 | 连接泄漏、隐式全局连接状态 |

### 6. 语言→std 黄金准则

领域翻译（表达式树 → SQL）**必须**在 `std/` 以 Arc 语言实现，编译器仅提供通用机制（表达式树构建、类型检查、代码生成）。方言差异、翻译逻辑、实体物化全部落在标准库领域层——编译器核心零领域能力。此为语言到 std 的黄金准则，ORM 为典型示范。

## 边界

- **表达式树机制**（`Expression<T>` 构建、Provider、Enumerable/Queryable、LINQ）见 [011](011-expression-trees-query.md)；本 RFC 只讲 ORM 如何消费翻译。
- **JSON 翻译**见对应序列化 RFC；**Protobuf** 见 [030](030-protobuf.md)。
- **DI / 连接生命周期原语**见 [023](023-math-tensor-di.md)。
- **编译器核心零领域能力**为架构红线，见标准库架构。
