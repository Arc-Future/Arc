# 适用场景与边界

## 适合

- 希望用熟悉的 **C# 式表面**写系统/工具/桌面/服务端逻辑，并得到 **AOT 原生二进制**
- 需要**编译期**查询翻译、表达式树物化（ORM、绑定、路由等）
- 构建 **Arc.UI** 桌面界面（ARML + wgpu）、**Arc.Web** / **Arc.Orm** / **Arc.Agent** 等应用面
- 团队用 AI 辅助编码，需要**单一惯用法**与结构化诊断，降低生成代码的歧义

## 不适合把本书当主入口的读者

| 需求 | 去哪 |
|------|------|
| 查阅已接受设计决策全文 | 仓库 [`docs/rfc/`](https://github.com/Arc-Future/Arc/blob/main/docs/rfc/index.md) |
| 改编译器 / 运行时 / ABI | 仓库 RFC + `crates/` / `runtime/`（本手册不展开） |
| 跟踪自举里程碑、成熟度门禁 tip | RFC 036 等内部成熟度文档——**非应用开发叙事** |

## 本书刻意不写什么

- RFC 001–052 目录浏览
- 编译器管线逐步实现细节（parse→HIR→…）
- `rt_*` 符号级 ABI 手册
- 实现规划、审查纪要、提案驳回备忘

进阶需要「为什么这样设计」时，见[设计决策入口](../12-advanced/design-decisions.md)。
