# Arc 语言宣言

> 立心立命 · 贯穿 Arc 全生命周期的设计脊梁

---

## 为何存在

智能正在重塑软件的编写方式。当代码的主要生产者从单一的人类，扩展到人类与智能体的协作体，编程语言必须重新回答三个问题：

**谁能读懂它？谁能安全地修改它？谁能预测它的行为？**

Arc 是为这三个问题而生的系统级语言。

---

## 命名

**Arc** 取「弧」——连接意图与执行的桥梁，连接人类思维与机器行为的纽带。

在智能时代，编程语言不仅是人与计算机的接口，更是人与智能体协作的公共协议。Arc 以编译期验证为弓，以原生性能为箭，以人机共写为的。

源码扩展名为 **`.as`**，编译器命令为 **`arc`**。

---

## 四元设计方程

```
Arc = 可读性 × 编译期安全 × AOT 确定性 × 人机协作性
```

四个因子**相乘**而非相加——任何一项为零，语言价值归零。

---

## 五条设计信条

### 第一信条：可读即可协作

程序首先是写给人和智能体共同阅读的文本。

- **前导类型范式**：类型在前、名称在后——函数签名即文档，局部上下文即可推断行为
- **单一惯用法**：每种意图只有一种推荐表达，消除歧义与随机选择
- **声明式查询**：以 Query 语法表达数据变换，而非命令式循环堆砌
- **确定性格式**：源码存在唯一的规范形式，人类与智能体输出一致

### 第二信条：安全在编译期完成

运行时崩溃是设计的失败，不是程序的常态。

- **资源所有权**：值类型栈上分配，引用类型共享所有权，编译期追踪生命周期
- **借用约束**：可变与不可变访问互斥，拒绝数据竞争
- **穷尽匹配**：分支必须覆盖所有可能，拒绝静默遗漏
- **显式错误链**：可失败操作在类型中标记，`?` 传播错误，失败不可被忽略

### 第三信条：行为在编译期确定

可预测性是系统软件的底线。

- **纯 AOT 编译**：源码直接变为原生机器码，无解释、无即时编译
- **无停顿式回收**：拒绝全局垃圾回收，资源释放时机可预测
- **零成本抽象**：泛型单态化，迭代器栈分配，抽象不引入隐式堆开销
- **确定性输出**：相同源码、相同工具链、相同目标平台，产生相同二进制

### 第四信条：代码即数据

程序的结构本身应成为可分析、可变换、可传递的数据。

- **表达式树（`expression`）**：Lambda 可被提升为编译期常量数据结构，写入只读段
- **Provider 模式**：下游消费者——查询引擎、验证器、规划器——直接遍历静态树，无需运行时解释；SQL 等具体翻译由标准库 Provider 实现，非编译器内置
- **双路径查询**：Enumerable 路径零成本迭代；Queryable 路径编译期树化——同一条 Query 语法，两种语义路径，编译器强制区分

### 第五信条：为人机共写而生

Arc 从设计原点出发，将智能体视为一等协作伙伴。

- **结构化诊断**：编译器输出机器可读的精确错误，附带修复建议
- **局部推理**：函数签名与邻近上下文即可理解行为，无需全项目图谱
- **能力显式**：外部效应——I/O、网络、系统调用——在类型签名中标记，沙箱可审计
- **契约可声明**：前置条件与后置条件作为类型系统的一部分

---

## Arc 的边界

### Arc 拒绝

- 隐式魔法与不可预测的运行时行为
- 以运行时反射替代编译期验证
- 多种等价写法并存的语法冗余
- 将智能体适配视为事后补丁而非设计原点

### Arc 追求

- 人类读得自然，智能体写得准确，编译器验得严格，机器跑得快
- 成为智能时代系统编程的公共协议
